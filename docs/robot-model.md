# Robot model

The main hero automatically loads `/models/robot-scroll.glb`; the entrance screen retains the logo. The model starts assembled. Scrolling through a 350svh sticky scene scrubs the Explode animation, then fades to black. Horizontal dragging rotates; +/− buttons zoom so wheel and vertical touch gestures remain available for scrolling. Reduced-motion users receive a static assembled viewer. After a drag, the model continues rotating about the axis implied by its horizontal and vertical movement at 6 degrees per second (one revolution per minute). Quaternion orientation updates allow continuous vertical and diagonal tumbles without camera pole limits. Rotation pauses during another drag or when the model fades out, and respects reduced-motion preferences. There is no real-time ground shadow.

## Rebuilding

The local source is `Small Drive Base.step` (excluded from Git). Preserve this file; do not publish it as a website asset.

Create a separate Python environment and install `cadquery-ocp`, `trimesh`, `numpy`, and `fast-simplification`, then run:

```sh
python scripts/convert_robot.py
python scripts/optimize_robot.py
```

The converter reads STEP assembly and face colors with Open CASCADE XCAF, then tessellates every solid with 1.2 mm linear and 0.5 radian angular tolerances. All parts are included, including small hardware and 6 mm plates. The conversion report records plate candidates for reference; these are rendered normally.

The GLB materials preserve the original STEP RGB colors and are fully opaque. For the website presentation, `RobotViewer.jsx` overrides them on load with opaque light gray (base color factor 0.6), zero metallicity, and 0.85 roughness. Viewer exposure is 0.45 for softer, dimmer lighting. STEP colors are converted to sRGB for the GLB material factors. The optimizer batches only geometry with matching colors, preserving the palette through simplification.

The optimization pass targets roughly 180,000 triangles with a minimum of 80 per part/material mesh, so the total can exceed that target. Nearby components are grouped into spatial cells subdivided by material. Groups animate radially based on their location; this is a presentation layout, not a mechanically sequenced assembly diagram. Central components remain nearer their original positions.

`convert_robot.py` writes assembled intermediate geometry to `/tmp/roboknights-assembled.glb`. `optimize_robot.py` writes the animated final GLB with an `Explode` clip from 0 to 1 second. The viewer scrubs this clip only on scroll/resize events, while a separate animation loop applies continuous free rotation after dragging.

## Model-viewer orientation guard

The project pins model-viewer 4.4.0 and applies `scripts/patch-model-viewer.mjs` after installation and before development/build commands. This version calls its AR scene-update hook on ordinary orientation changes, then attempts to add an XR menu to a null scene when AR is inactive. The patch skips that hook unless an AR session and scene exist. It preserves active AR updates. Vite excludes model-viewer from dependency prebundling so development uses the guarded source. Review this workaround when upgrading model-viewer.

Scroll framing uses `robot-framing.json`, generated by `scripts/measure_robot_framing.py` after optimization. Its 41 origin-centered radius samples enclose the animated parts in every rotation. The viewer interpolates these bounds and fits them to the smaller horizontal/vertical field of view with 10% padding, updating camera distance alongside scroll progress. Reverse scrolling restores the closer framing; resizing recomputes the fit while preserving camera angles.
